# 两阶段叙述：创作与系统层解耦

本页解释叙述正文、系统提取与前端阅读的完成边界，供修改生成链路或排查“已有正文却仍不能提交”时使用。第一阶段生成正文，第二阶段从正文提取状态；后处理结果进入会话与下一轮上下文。这样可以降低创作与格式纪律互相干扰的成本，但不保证模型判断正确或所有轮次只有两次调用。

> 最近核对：2026-10-11（`SceneManager.py`、`blueprints/chat.py`、舞台脚本与阅读用例的静态核对；未运行真实模型、SSE 或浏览器验收）。
> 本页由旧 `two-phase-narration.html` 讲解图整理；旧图中的速度对比是设计说明，实测日期与条件见[一轮耗时报告](../../perf/perf-round-latency.md)。

## 核心决策

1. **生成正文**：第一阶段专注剧情、玩家控制权与阅读约束，不要求同时输出系统控制 JSON。
2. **提取系统信息**：第二阶段按启用功能组装任务，输出结构化结果，程序负责解析、归一化及合法 ID 校验。
3. **写入与反馈**：程序更新环境、剧情日志、节点与分支，再在下一轮构建上下文时使用这些结果。

原单阶段方案让正文同时承担创作质量和系统格式，格式错误会影响整轮处理。拆分能分别设置预算和思考档位，提取降级时也能保留已经生成的正文；增加系统功能仍须配套解析、校验和落盘逻辑，不能只增加一段提示词。

## 第一阶段 · 只做叙述

叙述提示词包含创作、玩家控制权、总字数及舞台阅读约束。正文采用纯文本旁白和发言段，不要求模型分页或输出剧情控制 JSON；结构化误输出由服务端归一化。

底层真流式路径增量传递模型输出，前端可在第一阶段结束前阅读。首个 reasoning、首个正文和整轮完成是不同延迟，不能直接将“首字”视为模型首 token；实际时间取决于端点、思考档位、网络与正文长度。

## 第二阶段 · 只做系统层（独立轻量调用）

提取输入以本轮正文为主，不附完整对话历史；有分支生成需求时还附当前节点上下文与世界书背景。因此其成本不能一概写成只与正文长度有关。剧情模式始终提取；自由模式仅在选项、非叙事战斗模式或节拍状态需要时提取。调用使用 `stream=False`、`max_tokens=2048`、`thinking="none"`，按功能决定节拍完成、战斗、选项、节点标题、摘要及环境任务。

原始 JSON 与归一化结果的主要字段如下：

| 原始字段 → 程序字段 | 含义与约束 |
|---|---|
| `beat_complete` | 场景是否自然完成；作者要求玩家选择的节拍仍受服务端推进规则限制。 |
| `combat_trigger` → `combat` | 可用战斗遭遇与参数；程序处理模式与合法节点限制。 |
| `combat_scene` | 内置战斗所需的场面描述、可用敌人和强度；冻结插件模式不接受临时构造场面或参数。 |
| `choices` | 文本选项数组。 |
| `branches` | `label`、`intent`、`target_beat_id`；目标按当前合法节拍集合校验。 |
| `node_title` / `summary` | 当前节点标题与本轮剧情事实摘要；任务按条件加入。 |
| `environment` | 正文明示的地点、天气、时段与氛围变化，不应推测。 |

作者在节拍中写明的 `[COMBAT:<node_id>]` 由程序解析，优先于模型战斗判断。旧设计的 `[BEAT_COMPLETE]`、`[CHOICES]`、`[SUMMARY]` 已改成 JSON，不要恢复为正文输出协议。

### 解析与失败

标记提取解析剥离代码围栏、尝试完整 JSON 与对象定位，再归一化字段；空响应或 `finish_reason=length` 时重试一次。失败返回 `error` 与 `degraded`，路由据此标记二阶段降级，不能把空默认值当成“模型确认没有变化”。

原文的“直接解析 → 相邻引号修复 → 字段锚点扫描”属于正文 `DialogueSegment[]` 的结构化容错，不是 `_parse_extraction_json` 的三层保证。二阶段不增加正文改写调用，降级也不代表已经生成的正文必须整轮重做。

独立回忆摘要生成、注入、间隔配置与 SSE 已退休；这里的 `summary` 仍用于节点与剧情日志。`assess_deviation` 是另一个按条件触发的偏离评估调用，与本轮系统提取和已退休回忆摘要不同，不能宣称所有“第三次调用”都已删除。作者分支的确定性条件与结算见[剧情规则](story-rules.md)。

## 舞台阅读与完成交接

第一阶段正文在舞台对话框中按最多 140 个可见字符（Unicode grapheme）分页。末页可以增长，已有页边界固定；新增页只更新页数，不自动翻页。接收与二阶段处理期间允许阅读已有页，输入及选项提交仍受生成状态控制。

叙述 SSE 的两个完成边界：

- `text_complete {stream_id, narrative}`：第一阶段结束，正文经过结构化误输出归一化及 intra hook 后发送完整权威正文；二阶段尚未结束。
- `done {stream_id, round, phase2_status}`：正常后处理完成后发送，`round` 为服务端实际轮次；二阶段状态为 `completed`、`skipped` 或 `degraded`。`error` 为失败终态，之后不再发送 `done`；未收到完成事件的 EOF 按连接中断处理。

舞台保存当前预览页首字的原文偏移。正式旁白/台词分段保留权威正文中的起止范围，完成时将原文位置映射到对应正式页，原子切换正文、页码和说话人；已展示范围不重复打字。映射只接受精确内容或确定的前缀变化；无法可靠对应时，该轮继续保留完整纯文本预览，避免猜测跳页。

正文阅读与场景资源加载独立。等待下一轮时保留上一幕画面；最终头像、立绘和背景随后加载，图片或场景请求失败不隐藏正文。游标按会话、请求身份和变体隔离；显式回档从新游标重播。失败、取消及页面重启后的中断稿保留已收内容，不占用正式轮次，也不视为成功结果。

第一阶段提示词采用纯文本旁白段与发言段：完整发言由明确角色名和发言动词引出，连续表达集中在一组「」内。保留有意义的短回应，不设置台词最低字数，不替玩家发言。相邻同一已知说话人的台词在容量内可合并展示，不跨角色、未知归属或实质旁白合并。第二阶段继续只提取系统信息，不增加正文改写调用。
