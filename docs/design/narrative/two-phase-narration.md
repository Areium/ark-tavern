# 两阶段叙述：创作与系统层解耦

> 本文件原为 `two-phase-narration.html`（手写讲解图，已归档到 `archive/`）。这里给出等价的文字版并补上后加的机制。
>
> 状态：随代码演进；实现见 `src/SceneManager.py`。

## 核心决策

把「生成剧情」和「携带系统标记」拆成两个独立调用：

1. **第一阶段**只做叙述；
2. **第二阶段**只做系统层；
3. 第二阶段产物作为结果召回注入下一轮第一阶段，形成闭环。

**单阶段的问题**：一轮输出同时承担剧情质量与格式纪律两项职责，十分依赖模型能力，上下文越长越不守格式（掉括号、标记不全）。而格式错误对叙事应用的代价特别高——系统层解析失败，整轮都要重来。

## 第一阶段 · 只做叙述

- **提示词组装（干净上下文）**：不携带系统标记；包含创作、玩家控制权、总字数及舞台阅读约束。正文仍为纯文本，不要求模型输出分页或剧情控制 JSON。
- **LLM 叙述生成**：只输出剧情文本。
- **流式推送前端**：边生成边渲染，首字延迟 ≈ 模型首 token 时间。

## 舞台阅读与完成交接

第一阶段正文在舞台对话框中按最多 140 个可见字符（Unicode grapheme）分页。末页可以增长，已有页边界固定；新增页只更新页数，不自动翻页。接收与二阶段处理期间允许阅读已有页，输入及选项提交仍受生成状态控制。

叙述 SSE 的两个完成边界：

- `text_complete {stream_id, narrative}`：第一阶段结束，正文经过结构化误输出归一化及 intra hook 后发送完整权威正文；二阶段尚未结束。
- `done {stream_id, round, phase2_status}`：正常后处理完成后发送，`round` 为服务端实际轮次；二阶段状态为 `completed`、`skipped` 或 `degraded`。`error` 为失败终态，之后不再发送 `done`；未收到完成事件的 EOF 按连接中断处理。

舞台保存当前预览页首字的原文偏移。正式旁白/台词分段保留权威正文中的起止范围，完成时将原文位置映射到对应正式页，原子切换正文、页码和说话人；已展示范围不重复打字。映射只接受精确内容或确定的前缀变化；无法可靠对应时，该轮继续保留完整纯文本预览，避免猜测跳页。

正文阅读与场景资源加载独立。等待下一轮时保留上一幕画面；最终头像、立绘和背景随后加载，图片或场景请求失败不隐藏正文。游标按会话、请求身份和变体隔离；显式回档从新游标重播。失败、取消及页面重启后的中断稿保留已收内容，不占用正式轮次，也不视为成功结果。

第一阶段提示词采用纯文本旁白段与发言段：完整发言由明确角色名和发言动词引出，连续表达集中在一组「」内。保留有意义的短回应，不设置台词最低字数，不替玩家发言。相邻同一已知说话人的台词在容量内可合并展示，不跨角色、未知归属或实质旁白合并。第二阶段继续只提取系统信息，不增加正文改写调用。

## 第二阶段 · 只做系统层（独立轻量调用）

- **输入**：本轮叙述文本，**不带会话历史**，上下文成本 ∝ 本轮长度，与会话总长无关。
- **轻量 LLM 调用**：分类提取任务、**关闭思考模式**（`thinking="none"`）。
- **动态组装的任务列表**：战斗触发判断、选项生成、剧情摘要、环境变更。
- **扩展方式**：加一个系统功能 = 插一个任务 + 一个解析器；检定与 wiki 预取以钩子形式挂入这条链路。

## 结构化产物

第二阶段返回**一个 JSON 对象**（不是文本标记），字段为：

| 字段 | 含义 |
|---|---|
| `beat_complete` | 场景是否自然结束（角色离开、对话结束、行动完成等） |
| `combat` | 战斗触发判断 |
| `choices` | 选项字符串数组（向后兼容） |
| `branches` | 结构化分支数组，每项含 `label` / `intent` / `target_beat_id` |
| `summary` | 剧情摘要 |

> 早期设计用 `[BEAT_COMPLETE]` / `[CHOICES]` / `[SUMMARY]` 这类字面标记，**现已改为 JSON 提取**，`src/` 中不再有这些字面标记。

另有一条**独立的确定性路径**：作者在剧情节拍里硬编码的 `[COMBAT:<node_id>]` 由代码直接解析，**优先级高于模型提取**。

## 三条收益

1. **扩展性** —— 任务列表动态组装；加系统功能 = 插任务 + 加解析器，第一阶段一个字不用动。叙述质量始终不受系统逻辑侵入。
2. **成本** —— 两个调用完全解耦，可按各自任务特性异构配置：提取关思考模式、可用更小模型、更低推理预算；输入只有本轮叙述文本，长会话下成本曲线是平的。（`llm_backend_manager.py` 的 `narration_reasoning_effort` 即「按调用类型思考档位」。）
3. **可靠性** —— 三级 JSON 修复兜底：**直接解析 → 标点相邻引号替换 → 字段锚点扫描**。模型掉格式不再意味着整轮重来。

## 体验对比 · 感知响应速度

| | 单阶段 | 两阶段 |
|---|---|---|
| 用户何时可读 | 剧情 + 全部标记整体生成完 | 首 token 即开始流式叙述 |
| 标记提取的代价 | 计入首字等待 | 落在用户阅读叙述的时间窗里，几乎无感 |

## 后加机制（原图未覆盖）

- **结构化/气泡模式**：`SceneManager.parse_structured()` 把对话输出解析成 `DialogueSegment[]`，供气泡渲染路径使用。
- **分支生成**：提取产物的 `branches` 携带 `target_beat_id`，把选项与后续节拍直接连起来（`_normalize_branches_field` 会按当前节点校验目标）。
- **按调用类型思考档位**：叙述与角色对话走 `narration_reasoning_effort`，选项/回忆等分类任务始终关闭思考，见 `docs/perf/perf-round-latency.md`。
