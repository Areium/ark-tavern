# 横版实时动作关卡（第一阶段）

## 边界

会话创建时选择 `narrative`、`tactical` 或 `sideview`；模式创建后不可切换。剧情探索、战前简报、角色名册与世界书仍由原会话系统提供。`tactical` 继续使用 `CombatSession`、回合/卡牌/网格接口；`sideview` 使用独立运行记录和浏览器内的固定 60 Hz 模拟，不调用旧战斗的出牌或结束回合接口。

第一阶段提供一张可通关的“街区突破”关卡（3400 宽，守卫 / 弩手 / 重装守卫共 6 名，与独立演练同一套已配美术的地形，数值按会话主控属性调校）。其他遭遇暂回退到该关卡模板；剧情中的遭遇 ID 仍进入战斗历史。平台、障碍、危险区、敌人、出生点、出口和奖励由 `data/sideview_levels/default.json` 描述。反复往返的大地图与能力解锁开路不在本阶段。

## 交接契约

- 剧情战前简报选择打法后调用 `POST /api/sessions/<id>/sideview/start`，提交 `encounter_id`、可选的 `approach_id` 与 `operator_name`。返回 `kind: sideview` 和 `state`：`runId`、冻结的 `level`、主控战斗数值、援护者名称、初始快照及状态。避战与检定沿用现有 `approaches/check/avoid` 响应形状。`enemy_scale` 在横版中缩放敌人 HP/伤害，`first_strike` 提供开局先手优势，主控 `hp_penalty` 改变初始 HP。
- 前端 `features/sideview/` 独立执行输入、重力、平台/障碍碰撞、闪避、攻击、技能、敌人 AI、镜头与 PixiJS 7 绘制。固定步长为 1/60 秒；渲染帧与模拟步长分离。首版单人主控，队友通过援护技能参与。关卡可配置 `victoryCondition`：`clear_and_exit`（默认）要求清敌后到出口，清敌前出口前有全高度空气墙；`reach_exit` 只要求抵达出口。
- `POST /sideview/save` 存储版本化快照：主控与敌人位置/HP、冷却、累计时间及出口状态；`suspended: true` 表示保存并离开。`GET /sideview/state` 返回持久快照，恢复时再以 `suspended: false` 进入活动态。运行记录保存在该会话 `overrides.json.sideview_run`，后端重启后仍可读取。
- `POST /sideview/complete` 接收 `runId`、`levelId`、胜败、时长、击杀、受伤、剩余 HP 和终局快照。服务端以保存的关卡配置决定奖励，校验身份、边界、敌人集合、生命值单调性、出口与存活条件及保守可达时间。前端提交的奖励字段不起作用。`POST /sideview/abandon` 放弃本次行动，不发奖励。
- 结算以 `pending_settlement` 记录进度，角色成长、背包和战斗历史对同一 `runId` 只写一次；失败可重试。主控 HP、最大 HP 与胜负写到 `sideview_status`，下次关卡同角色继承 HP；战败为保证剧情继续，下一场按最大 HP 的 25% 复苏。完成后返回剧情自动叙述指令。

浏览器模拟意味着本地客户端拥有位置和命中状态。服务端能拒绝结构无效、即时或明显不可能的终局，无法证明玩家输入轨迹；若未来需要防恶意客户端刷奖励，应采用服务端复算或可信事件记录。本阶段的结算幂等约束针对同一运行记录，重新开始一局仍是新的战斗。

## 战斗机制

全部在 `simulation.ts` 的确定性步进里实现，不进入存档快照（快照仍是 version 1，恢复时这些瞬时状态归零）。

- **三段连击**：连按或按住近战，在 0.35 秒窗口内接续；倍率 1.0 / 1.1 / 1.6，第三击击退更远并**打断普通敌人的蓄力**（硬直 0.45 秒）。前两击只造成受击闪白与小幅击退，不打断，避免按住攻击把敌人永久压制。攻击键有 0.18 秒输入缓冲。
- **精英霸体**：重装守卫对连击只受 30% 击退、不被打断；技能（硬直 0.6 秒）与援护（0.5 秒）能打断。精英蓄力后沿锁定方向**突进斩**（0.24 秒，520 px/s），渲染器画出整条突进通道。
- **弩手**：玩家贴近（170 px 内）时后撤，射击瞄准玩家胸口（带纵向速度），弹道穿过单向平台、被实心体阻挡。
- **守卫**：蓄力结束时判定 `guardStrikeBox`；AI 行走不会走下平台边缘（击退仍可能把敌人打下坑），撞墙会掉头巡逻。
- **极限闪避**：闪避期间被攻击（非地形伤害）判定命中时，每次闪避奖励一次：技能冷却 −1.5 秒、额外 0.4 秒无敌、短暂停顿。
- **命中停顿**：命中 0.045–0.1 秒、受伤 0.06 秒冻结世界；期间的按键按上升沿排队，恢复后生效，不会丢输入。`elapsed` 照常累计，不影响服务端最短通关时间校验。
- **坠落**：扣 25 生命后回到最近的**安全落脚点**（双脚都踩在实体上、两侧 48 px 内无危险区），而不是关卡起点。
- **单向平台**：厚度 ≤ 32 px 的平台默认可从下方和侧面穿过、只在下落时站上；关卡可用 `oneWay: true/false` 显式覆盖。厚地面与障碍箱始终是实心。
- 连击数（不受伤的连续命中，2.5 秒内续上）与最高连击只用于 HUD 与演练结果，服务端忽略 `bestChain`。

## 表现与输入

- 渲染器把平台、障碍、危险区的描边与后备色块**只绘制一次**；每帧只重绘出口、预警、血条和特效。伤害数字用复用的 Pixi `Text` 池。
- 预警：守卫脚下橙色条随蓄力填满并标出斩击范围；弩手画虚线瞄准线；精英画红色突进通道。死亡的敌人播放 Spine `Die` 后淡出，读档时已阵亡的敌人不重播。
- 震屏、受伤红色暗角、低血量（< 30%）脉冲、镜头按朝向前瞻；`prefers-reduced-motion` 下关闭震屏、数字漂浮、脉冲与镜头缓动。
- HUD：技能按钮上的冷却填充、连击计数与三段指示、附近精英的具名血条。
- 手柄（标准布局）：摇杆 / 十字键移动，A 跳跃，B / LB 闪避，X / RT 近战，Y 技能，RB / LT 援护，Start 暂停 / 继续。

## 关卡编写与校验

`load_level` 调用 `validate_level` 做结构与边界校验：`schemaVersion`、宽高范围、平台至少一个、所有矩形尺寸为正且在关卡内（危险区允许向下超出 80 px 表示坑底）、危险区 `damage`、出生点与出口在界内、敌人 ID 唯一、`kind` ∈ guard/ranger/elite、`hp` 为 1–9999 整数、`damage/speed/range` 在范围内、巡逻区间有序、`oneWay` 为布尔、`rewards.xp` 为非负整数。错误信息带字段路径。是否好玩、能否通关不由校验保证：前端 `simulation.test.mjs` 用一个“追最近敌人、遇坑跳、预警闪避”的简单策略实打默认关卡，必须在 90 秒模拟时间内胜利；改动地形或数值后先跑它。

## 美术资源

横版场景使用为“废城边界 · 雨幕行动”生成的雨夜废城背景、石钢地表、运输障碍箱和红色晶体危险带。素材位于 `frontend/public/assets/sideview/`，由 PixiJS 直接加载；原第三方工业视差图层与金属图集已从项目移除。背景是通用街区突破场景的美术方向，不表示所有剧情遭遇都发生在同一地点。

玩家与守卫优先复用项目现有的 Spine 战斗小人及动画。演练主控使用临光；其 Spine 加载失败时从现有角色皮肤接口加载立绘。Spine 文件位于 `data/worldbooks/content/characters/<角色>/spine/`，由现有资源接口提供；这些第三方角色素材被 `.gitignore` 排除，不随代码仓库分发。没有对应文件或加载失败时，横版关卡保留可识别的后备角色显示，碰撞与结算不依赖美术资源。

## 雨幕街区的移动与环境反馈

- 敌人优先使用完整的 `Move_Loop` / `Run_Loop`，避免把 `Move_Begin`、`Move_Down` 等过渡动作误当循环；播放速度随移动速度变化，攻击动画仍按原有完整动作链播放。
- 当前临光泳装的 Front / Back 战斗骨骼都没有原生跑步循环。为保留同一皮肤，移动时对现有左右腿 IK 目标施加交替步态，并配合重心前倾、轻微起伏、空中姿态和落地压缩。它是程序化补偿，不是新增的官方跑步素材；其他没有相同 IK 骨骼的模型只保留重心反馈。
- 新增脚步水花、起跳涟漪、落地飞溅和定向冲刺尾迹；脚步按实际地面移动距离触发，顶墙、待机和空中不会持续冒水花。模拟特效总数仍限制为 90。
- 雨夜街区增加路灯光锥、下垂电缆、破损基座、湿地反光与角色接地阴影。场景物件从现有平台几何确定性布置，最多 32 件，避开危险区、障碍和出口。
- 路边罐体和矮警示灯可以被近战、范围技能或闪避冲撞击碎；灯灭后留下碎片，破坏只产生视觉反馈，不修改地形碰撞、不造成伤害、不增加击杀或奖励。它们是临时场景状态：暂停仍保留，保存后重新进入会复原；version-1 快照、后端校验和剧情结算契约保持兼容。
- 临近可破坏物且附近没有敌人时显示操作提示，进入战斗时隐藏。减少动态效果时关闭补偿步态/重心晃动/反光波动，保留静态接地反馈并减少碎片数量。
