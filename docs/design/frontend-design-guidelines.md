# Ark Tavern 前端设计风格指南

面向 PC 端的前端视觉设计。整体追求克制、清晰、有叙事氛围的质感，通过排版、留白、配色和细节的一致性提升完成度，而不是靠更多文案与装饰填满页面。

## 固定窗口尺寸与验收基准

前端页面、组件、布局和交互按以下五组固定尺寸进行开发和桌面验收。尺寸指窗口内容区的逻辑像素（浏览器验收时对应 CSS 视口），不包含系统标题栏与边框，不按屏幕的物理像素或缩放后的截图尺寸计算。

| 内容区尺寸 | 开发定位 |
| --- | --- |
| 1280 × 720 | 紧凑桌面基准，重点检查纵向空间和主要操作可达性 |
| 1400 × 900 | 默认窗口与主要设计基准 |
| 1600 × 900 | 常规宽屏基准 |
| 1920 × 1080 | Full HD 基准 |
| 2560 × 1440 | 2K 基准，检查阅读宽度、留白和面板扩展 |

- 尺寸清单以 `frontend/src/shared/windowSettings.ts` 为唯一代码来源；变更预设时同步设置选项、默认窗口和本表。
- 每次前端变更在这五组视口检查受影响页面的布局、主要操作、滚动边界、弹窗与键盘焦点。不得仅按当前开发者桌面的任意尺寸设计，也不为每个尺寸维护一套重复页面。
- 用户仍可自由拖动窗口边缘；现有窗口最小限制保持不变。任意拖动所得尺寸不作为设计或验收矩阵的指导基准，不要求新增手机窄屏验收。
- 同时检查「窗口」「窗口全屏（最大化）」和「全屏」切换后的尺寸更新、内容滚动和恢复窗口行为。最大化使用当前屏幕工作区，全屏使用完整屏幕；它们不增加任意屏幕尺寸的开发矩阵。
- 屏幕可用空间不足时，对应普通窗口预设不可用；应使用具备足够空间的桌面验证实际调整，或以浏览器视口验证该固定尺寸的布局。浏览器布局检查不能替代 Electron 的窗口模式与尺寸控制验收。

## 整体风格

- 保留故事、角色与世界书的主题感，同时保持现代桌面工具的利落。氛围来自内容与少量视觉特征，不把每个页面都做成宣传海报。
- 一页有明确的视觉重心。主内容与主操作突出，次要信息安静退后，不让所有标题、卡片和按钮争夺注意力。
- 同类页面延续相同的排版与组件语言。不要每新增一个功能，就换一套圆角、阴影、按钮和配色。

## 文案做减法

- **主标题下不生成描述性副标题、功能介绍或宣传文案。** 页面用简洁标题直接进入内容或操作区，不默认套用“英文眉题 + 大标题 + 一段介绍”的结构。
- 分区标题和卡片标题也不附带重复解释。能从名称和布局理解的功能，不再写“在这里管理……”“轻松探索……”“打造专属……”等句子。
- 例如，世界书页面保留“世界书”、搜索和创建入口即可，不追加“在这里管理你的世界设定，开启无限冒险”。
- 按钮和标签使用简短、具体的词语，如“新建会话”“导入”“保存”，不用文学化表达替代操作含义。
- 必要的字段说明放在对应控件附近，较长帮助按需展开；错误原因、危险操作后果、保存状态等必要信息仍须清楚可见。
- 不为填补空白编造统计、标签、徽章或提示。以上约束针对界面文案，不删减剧情正文、角色介绍和用户创作内容。

## 用排版和留白建立层次

- 标题、正文、辅助信息形成少量清晰层级，优先用字号、字重与间距区分，不依赖彩色文字和粗重边框。
- 标题简洁有分量，但不占据过大的首屏空间；正文舒适可读，不靠缩小字体或降低对比度制造“精致感”。
- 对齐边缘，统一组内间距和组间留白。相关内容靠近，不同任务适度分开，让布局本身说明关系。
- 避免卡片套卡片、每行都加分隔框。简单列表可以直接排列，只有真正独立的内容才需要独立容器。
- 留白是结构的一部分，不必用说明文字或装饰填满；也不要留下与内容密度不相称的巨大空区。
- 长文保持适宜的阅读宽度，密集编辑区保证操作空间。桌面窗口变化时仍保持对齐与主次关系。

## 配色与材质

- 以低干扰的背景和表面色为底，少量强调色用于主操作、选中和重要状态。不要让每张卡片都有不同的高饱和底色。
- **按钮不使用渐变色**，包括普通、悬停和按下状态；使用纯色、轻底色或描边，通过细微色差表达反馈，不叠加渐变高光。
- 除深色模式或主题明确需要外，背景、卡片和按钮避免大面积过深的颜色，优先柔和、低饱和的浅色，减少深色块与浅底之间生硬的反差。文字与图标仍要清晰可读，不通过淡化文字降低必要对比度。
- 层次优先来自细腻的明度差、细边框与留白。非按钮区域的阴影、渐变、透明和模糊也应克制，只在确实有助于区分前后层时使用，避免满屏发光和玻璃效果。
- 保持已有主题的性格：默认主题干净清晰；PRTS 偏冷色终端、细线与切角；酒馆手札偏纸面、墨色与温暖点缀。不要在同一页面混搭互不相容的材质。
- 角色与场景图片可以承担主要氛围，背景纹理保持低存在感，不抢文字与操作。图片裁切自然、比例稳定，不拉伸、不随意裁掉人物识别部位。
- 同一主题内统一圆角、描边、阴影和透明度；不同皮肤可以有自己的形状语言，不强求全部圆角化。

## 图标与装饰

- **界面标题、导航、按钮、标签和状态提示不使用 Emoji。** 也不使用字符画或零散 Unicode 符号冒充功能图标。
- 需要图标时使用 SVG，优先复用项目现有的 `frontend/src/components/AppIcon.tsx`，保持描边、尺寸、颜色和对齐一致，不混用多套图标风格。
- 图标用于帮助识别，不给每个标题和每段文字机械添加图标；没有明确作用时可以不用。
- 重要或不熟悉的操作保留文字，纯图标按钮提供清楚的名称与提示。视觉简洁不能以难以理解或无法键盘操作为代价。
- 品牌标志、角色立绘等继续使用已有图像资源；SVG 要求针对功能图标，不要求把内容图片全部矢量化。

## 不同页面的表达

- **首页**：突出品牌与进入、继续体验的入口，背景营造氛围，菜单清晰。不堆功能介绍、无意义统计或装饰性徽章。
- **会话与内容管理**：紧凑、有序，直接呈现列表、筛选、编辑与主操作。避免每页都放巨大的横幅和介绍区。
- **对话与舞台**：让剧情、角色和选择成为视觉重心，工具控件退居次位，避免装饰打断阅读。
- **战斗与节点图**：信息关系与操作状态优先，特效服务于反馈，不遮挡关键内容，不用统一外观掩盖不同状态的含义。

## 交互也要有质感

悬停、选中、焦点、加载与禁用状态清楚且统一；反馈及时，过渡轻量，不让按钮跳动、内容无故位移或动画拖慢操作。精简界面时仍保留必要的状态反馈、可读对比度与键盘焦点，不隐藏真实功能和重要控制。

完成后重点看：第一眼是否知道该看哪里、做什么；是否还有可以删除的重复文案与装饰；同类元素是否像同一套设计。能通过删减获得更清晰的界面，就不再叠加视觉效果。

## 项目边界

沿用现有皮肤体系，战斗页不换肤；皮肤生成区的修改规则、工程流程与测试要求见 [AGENTS.md](../../AGENTS.md)，模块入口见 [架构索引](../architecture.md)。本指南不规定逐项尺寸、API 或测试步骤，也不授权改变功能与数据含义。
