# Ark Tavern 前端设计避坑清单

本文档是 AI 在本仓库进行前端开发时必须遵守的**禁令清单**。只记录当前前端设计中被明确要求避免的问题；AI 默认就会遵守的通用设计规范（对比度、对齐、间距、可读性等）不在此重复。

以下条款为硬性约束，不是建议。违反任何一条即视为设计不合格。

---

## 第 1 条（最重要）：标题下不要加入副标题和描述性文字

**这是本清单中最重要的一条，优先级高于其他所有规则。**

- 保持前端界面简洁。**不要自作主张为标题、功能模块增加副标题、功能介绍、宣传文案或任何补充描述。**
- 页面用简洁标题直接进入内容或操作区。禁止默认套用「英文眉题 + 大标题 + 一段介绍」的结构。
- 分区标题和卡片标题同样不附带重复解释。能从名称和布局理解的功能，一律不写「在这里管理……」「轻松探索……」「打造专属……」之类的句子。
- 例如：世界书页面保留「世界书」、搜索和创建入口即可，不得追加「在这里管理你的世界设定，开启无限冒险」。
- **如果某个功能按钮难以理解，由用户主动提出补充；AI 不得在一开始加入解释性文字。**
- 不为填补空白编造统计、标签、徽章或提示。此约束针对界面文案，不删减剧情正文、角色介绍和用户创作内容。

## 第 2 条：禁止使用 Emoji 和符号冒充图标

- **界面标题、导航、按钮、标签和状态提示中一律不使用 Emoji。**
- 同样禁止使用字符画或零散的 Unicode 符号冒充功能图标。
- 需要图标时使用统一的 SVG，保持描边、尺寸、颜色和对齐一致，不混用多套图标风格。
- 图标仅用于帮助识别；没有明确作用时不用图标，也不得用 Emoji 或符号代替。


## 第 3 条：验收不用考虑窄屏（手机端）

- **前端验收只针对桌面端宽度，不需要适配或检查手机屏幕。**
- 不为窄屏单独调整布局、组件或交互，不把窄屏表现作为验收项。

---

## 附：桌面端验收尺寸基准（项目固定口径）

与第 3 条对应：前端页面、组件、布局和交互按以下五组固定尺寸进行开发和桌面验收。尺寸指窗口内容区的逻辑像素（浏览器验收时对应 CSS 视口），不包含系统标题栏与边框。

| 内容区尺寸 | 开发定位 |
| --- | --- |
| 1280 × 720 | 紧凑桌面基准，重点检查纵向空间和主要操作可达性 |
| 1400 × 900 | 默认窗口与主要设计基准 |
| 1600 × 900 | 常规宽屏基准 |
| 1920 × 1080 | Full HD 基准 |
| 2560 × 1440 | 2K 基准，检查阅读宽度、留白和面板扩展 |

- 尺寸清单以 `frontend/src/shared/windowSettings.ts` 为唯一代码来源；变更预设时同步设置选项、默认窗口和本表。
- 每次前端变更在这五组视口检查受影响页面的布局、主要操作、滚动边界、弹窗与键盘焦点。用户自由拖动窗口所得的任意尺寸不作为设计或验收基准，也不要求新增手机窄屏验收。
- 同时检查「窗口」「窗口全屏（最大化）」和「全屏」三种显示模式切换后的行为。
