## 1. 产品范围

用户本轮明确：优先本地单机的安装、运行、卸载链路；不考虑云端部署、游戏过程中升级插件或冗余状态存储。补充确认：剧情回档属于基本功能，公共结算是项目基石，两者必须参加首轮验收。

用户已确认采用“受信任插件 + 隔离界面 + 宿主管理存档”：信任插件计算和修改游戏内容，不做反作弊；允许安装者信任的 Python 原生插件通过独立子进程执行。安装者承担原生代码信任风险，项目不提供恶意原生代码沙箱，不承诺阻止其访问当前系统用户有权访问的文件、网络或本机凭据。这一决策正式取代此前“必须阻止恶意插件修改系统文件”的要求。

首轮闭环为：安装精确版本 → 创建会话 → 运行真实玩法 → 保存/恢复 → 公共结算 → 剧情回档 → 退出会话 → 删除依赖会话后卸载。回档和结算不能仅留下接口或测试替身。

首轮以一个官方玩法验证完整链路，再迁出另外两种。最终交付必须覆盖三种官方玩法的真实独立包、默认安装、无战斗插件会话，以及无需修改宿主源码或重建宿主前端即可安装的第四种玩法；不先建设所有通用扩展面。这里的官方玩法默认安装是插件目标，不改变世界书示例必须由用户显式安装的现行原则。

桌面端是完整游戏体验的主入口。首轮保留官方玩法的完整界面嵌入与指定 UI 区域替换，并向第三方开放同一开发通道；不能将插件限制为数据脚本或一个固定小面板。暂缓的是多个插件同时争抢同一区域的仲裁、共享依赖生态与非必要工具页。世界书编辑器扩展仍是后续目标。

### 桌面体验与可复用核心

- 核心提供世界书、叙事、会话数据、公共结算及存档接口，不依赖 Electron 或某个玩法的 UI。未来外部项目可以只调用所需能力；不以先完成完整 headless SDK 为首个官方玩法的前置。
- 桌面端保留世界书工作台、会话入口、插件管理和完整游戏空间。现有酒馆是核心的主要客户端与产品形态，不退化成只能调接口的数据管理器。
- 玩法插件通过公开 SDK 接入核心及桌面展示；官方与第三方使用相同的包、生命周期、视图和数据契约，不给官方包保留宿主静态 import 或私有接口捷径。
- 用户进一步收敛：不需要大型引擎的原生嵌入，目标是让其他作者在酒馆桌面基础上开发完整游戏。提供完整游戏内容区及启动、输入上下文、快照、恢复、结果和停止接口；作者可使用网页技术制作游戏，不强制 React，不建设原生窗口嵌入框架。

### 桌面展示契约

| 能力 | 首轮边界 |
|---|---|
| 完整游戏空间 | 当前玩法可提供整个游戏内容区，自行组织画布、HUD、菜单和内部布局；不能只允许固定组件中的小区域 |
| 区域扩展与替换 | 提供明确命名的侧栏、行动区和消息呈现接口；当前会话绑定玩法可以追加或替换声明的区域，不依靠修改宿主源码 |
| 退出与管理 | 宿主保留始终可到达的退出、故障恢复和插件管理入口，插件视图关闭后恢复宿主默认界面 |
| 多提供者 | 首轮一个活跃玩法决定会话展示；重复声明明确报错，不实现多个无关插件竞争布局的自动仲裁 |
| 开发通道 | 官方包使用公开模板/SDK开发，第三方示例从独立目录打包安装；文档列出稳定扩展点，不要求第三方 fork 宿主 |

首轮以现有官方玩法证明桌面游戏内容区与 UI 替换，并用独立第三方示例验证公开通道。作者可以采用 HTML/CSS、React、Canvas、PixiJS 等技术构建玩法；SDK 处理与宿主的交互，不替作者实现游戏规则。原生引擎窗口嵌入、Unity as a Library、画面传输和跨引擎窗口适配不属于当前或预设后续任务。

外部项目使用核心与桌面内嵌玩法共享数据协议。需要参与酒馆回档的公共/私有状态由核心统一保存，不让引擎自己的存档成为第二份权威数据；仅使用世界书查询的外部程序无需接入整个会话系统。

## 2. 运行和管理规则

- 同一数据根只有一个本地写宿主；同一会话的保存、结算、回档串行提交。单机仍有 UI、后台请求与子进程，保留基本互斥和状态版本检查。
- 首轮只允许一个活跃的战斗插件运行实例。切换会话或回档前先停止旧实例；宿主递增执行代次，拒绝迟到响应，再装载目标状态。无需维护运行中交接协议。
- 安装、正常启停、授权变更和卸载在插件管理状态完成，先退出活跃插件会话；遇到占用明确拒绝，不自动热保存、热替换或迁移。
- 停止有有限等待，超时可由宿主销毁 iframe/回收进程；无法确认停止时阻止后续写入和卸载。恢复以最近一次已确认保存为准，不承诺保存失败时保留所有临时帧。
- 紧急禁止执行仍可立即阻断后续能力调用；这不等于原生代码的 OS 权限已被撤销。正常重启后不得自动恢复已停用插件。
- 保留 pluginId + version + digest 身份。不同版本可作为独立安装项；新版本新建会话，旧会话不改绑。没有运行中升级、存档迁移或自动选择最新版。
- 卸载前列出依赖会话；用户通过独立删除入口先删除会话，实际删除成功后才解除引用。导出的离线备份不阻止卸载；恢复备份必须重新取得原精确包。

## 3. 模块职责

| 模块 | 责任 | 不承担 |
|---|---|---|
| 包管理 | 静态校验、安装目录、精确版本登记、启停、依赖会话检查、卸载 | 执行安装脚本、自动更新、云端同步 |
| 运行器 | 加载入口、传入限定上下文、动作派发、私有状态读写、停止/重建 | 修改宿主全局数据、管理版本迁移 |
| 会话存储 | 当前公共状态、剧情、插件状态、节点快照、结算收据的统一事务 | 两份可独立修改的当前存档 |
| 公共结算 | 校验数据格式与当前会话作用范围、一次提交、重复请求返回原结果 | 游戏数值公平性验证、通用反作弊或恶意本机代码隔离 |
| 玩法插件 | 规则、胜负、奖励计算、私有状态、视图及同版本恢复 | 经 SDK 直接写宿主文件/SQL、获取模型密钥；绕过 SDK 直接改库不受支持 |

插件界面使用隔离 iframe，可承载完整 React/Canvas/PixiJS 页面；作者自带构建产物。界面不进入宿主上下文 trusted-ui，不开放 Electron/Node 内置模块、任意 shell 或文件路径接口。主进程/后端的插件 SDK 只接受作用于已绑定会话的结构化请求。这里限制的是宿主公开接口和界面权限，不是对原生插件全部行为的 OS 限制。

执行模型已确定：网页界面及网页玩法逻辑，按需配合独立 Python 子进程复用原生玩法；不要求所有玩法迁至 JS/Wasm，不建设任意语言运行平台或 OS 沙箱。独立子进程用于启停、异常处理和故障隔离，普通 Python 子进程、-I 参数、SDK 白名单和 Job Object 均不能被称为恶意代码权限沙箱。官方与第三方使用相同契约；“官方”身份不绕过包管理和数据接口。

原生扩展的安装/启用界面明确说明它会作为本地程序运行，由安装者判断来源是否可信；权限声明不显示成已被 OS 强制限制的权限。包管理仍只静态安装，不运行安装脚本。模型调用由宿主代理，SDK、启动上下文和日志不主动下发密钥，但不承诺抵御恶意原生进程读取本机凭据。直接访问文件或网络产生的外部副作用不参与剧情回档，卸载也不保证撤销它们。

界面隔离仍要求 Electron renderer sandbox、contextIsolation、关闭 Node integration，iframe 不开放同源、顶层导航或下载权限，CSP 默认拒绝网络/子框架。IPC/HTTP 逐操作鉴权，不提供任意文件、命令、URL 代理；导入包的 ZIP/链接/路径校验同样保留。宿主保存/导出只写自身控制的存档位置，用户选择目录的能力不传给插件界面。参见 [Electron 安全说明](https://www.electronjs.org/docs/latest/tutorial/security/)与[进程沙箱](https://www.electronjs.org/docs/latest/tutorial/sandbox)。这些要求覆盖界面和宿主接口，不能扩展为对外部 Python 进程的隔离保证；当前实现仍须实际验收。

玩法包优先自包含。首轮不新增共享库版本范围求解；确实无法打包的依赖只声明精确版本并校验。按上述展示契约开放完整内容区与命名区域替换，重复贡献报错，不建设多个提供者争抢宿主面板的选择系统。视图替换是公开挂载契约，不要求运行插件进入宿主 JavaScript 上下文。

SDK 暴露启动、动作、保存、恢复、停止和结果提案；精确身份、执行代次、状态版本、请求 ID 与取消由宿主/SDK 管理。复用现有接口中可用部分，不为“精简”另造一套同功能协议或重写玩法引擎。

## 4. 一个会话事务域

采用现有 SQLite 事务能力承接需要一起提交的会话可变状态：公共角色/物品状态、剧情与记忆、插件私有 JSON、节点快照、运行完成标记和结算收据。相关数据必须在同一个实际数据库事务内；不另建每会话数据库后再和全局注册库协调提交。

世界书源文件、图片音频与不可变插件产物继续存文件。普通文本/JSON 存档可作为导出视图，但不能再作为并行写入的权威当前状态。插件参与回档的状态必须经 SDK 交给宿主，不直接改库或另建第二份权威存档；这属于接入契约，不是对恶意原生代码的强制权限隔离。运行内存是可丢弃的缓存；数据库提交成功才发布新内存状态，失败则重读已保存状态。

不建设会话当前态的双写、双读、冗余副本同步，也不继续扩展五文件 journal 与 SQL companion 的跨存储结算。通过统一 SessionStore 接口替换相关消费者，切换完成时清理被替代路径，不能长期保留新旧两条运行路线。

历史快照是回档功能所需的不同时间状态，不是第二份可写当前存档。首轮保存完整可恢复快照即可，不增加跨副本证明、增量快照引擎或快照去重平台。包/资源保存为不可变引用；删除会话和引用登记使用同一事务，不依赖后台补齐重复引用表。

文件安装/删除仍有最小生命周期边界：临时目录验证后发布，再登记可用；失败不显示可运行。卸载先在互斥区标记不可运行并重验引用，再删除对应安装文件；失败留下可诊断状态，启动时完成清理。数据库事务不覆盖外部文件操作。

外部模型调用不能与本地存档原子提交。保留最小请求 ID、pending/成功/失败/unknown 和结果记录；未知结果不自动重复调用。回档恢复游戏状态，不撤销已发生的模型调用和费用。

这是一项明确的存储改造，不声称已有代码天然满足。实施集中在会话数据接口及其剧情/结算消费者，不重写世界书、媒体、LLM 客户端或全部玩法。开发夹具按新结构重建；本轮不转换或删除真实用户存档。

## 5. 公共结算和回档

### 公共结算

用户已确认信任插件的游戏内容：插件计算胜负、奖励和成长，宿主不再用另一套 validator 独立证明玩法正确性，不验证是否作弊或是否符合原玩法平衡。不保留独立动作观察/随机收据/完整效果前后镜像证明作为结算前提。

首轮必须覆盖当前玩法实际的经验、成长/属性、物品、角色状态和剧情结算，不能用仅支持条件或一条历史记录代替完整结算。玩法公式留在插件；宿主只接受明确类型的效果，不接受任意路径写入或 SQL。哪些成长字段属于公共数据、哪些属于玩法私有状态，在首个官方包清单中逐项说明，保持原玩法效果。

提交使用唯一操作 ID 和预期状态版本；宿主一次性检查并提交公共变化、插件最终状态、剧情结果和完成收据。同一 ID 同输入返回原结果，不再发奖；同 ID 不同输入报冲突。确认界面采用固定提案，状态变更后重新确认。提交失败不发布任何半完成效果。

保留类型、有限数、数据容量、协议可表示范围和当前会话的角色/物品作用范围检查，这些用于可靠保存与防止越界；不设置额外“奖励过大即作弊”的公平性门禁，不将用户确认冒充独立规则验证。游戏规则允许的变更由插件决定。

### 剧情回档

节点快照包含公共状态、剧情/记忆、绑定的精确版本、插件私有状态和相关结算状态。回档先停止实例，确认目标可恢复，再在同一事务恢复目标分支状态并更新执行代次，最后重新启动对应版本。

回档前已发生的奖励必须随公共状态撤回；旧分支完成收据保留历史含义，不能让新分支误判为已结算或重复领取。回档不通过重跑模型、随机过程或旧动作来重建结果。插件保存随机状态或动作已确认结果即可，不默认建立独立随机证据账本。

存档损坏、插件缺失或恢复失败时保留最后一个完整状态并报错，不退回另一种玩法、不丢弃进度。原生进程的退出仍需确认，更新一个状态字段不能代替真实停止。

## 7. 实施顺序与验收

实施记录应让读者先看到当前状态、提交和下一步；详细运行过程进入专项记录或归档，不将测试数量作为产品完成度。以下是放行顺序与条件，具体勾选状态以权威 `task.md` 为准。

1. **确认精简边界。** 已确认受信任 Python 原生插件、隔离网页界面、宿主管理存档及唯一会话事务域；公共结算信任游戏结果。设计决定已完成，实现和验收按上方状态分层理解。
2. **一个官方玩法贯穿全链路。** 优先用现有战术的一场真实战斗验证安装、运行、保存/恢复、完整公共结算、剧情节点回档和删档卸载；先做必要 SessionStore 切片，边迁玩法边校准接口，不先建设全部通用平台。具体选用内容沿用现有有效节点，不重新设计战斗数值。
3. **迁出其余官方玩法。** 三包各自包含真实规则/UI/资源，只安装该包也能运行；默认安装走相同包管理，无官方 ID 生命周期特权。第四独立包通过公开 SDK 验证桌面嵌入和指定区域替换，无需改宿主或重建宿主。
4. **收尾交付。** 完成受影响代码回归、官方包独立构建、当前版本真实 PC 浏览器与 Electron 验收；清理被替代路径后合并。存档导出导入只服务当前结构，不重新引入携带可执行包和旧版迁移。

首轮必须逐项有真实证据：

| 验收 | 成功条件 |
|---|---|
| 安装运行 | 在隔离新数据根安装完整官方包，重启后仍能发现并运行；格式、路径或完整性校验失败的包不执行，静态校验不代表无恶意代码 |
| 桌面展示 | 官方包实际占据完整游戏内容区并替换至少一个命名区域；切换/退出后宿主恢复，键盘焦点与窗口尺寸正常 |
| 对外通道 | 独立示例使用公开模板/SDK实现相同展示和数据接口，安装时无需修改宿主；不能只测试官方私有入口 |
| 信任与接口边界 | 原生执行风险明确呈现，安装不执行脚本，SDK/启动上下文/日志不主动下发密钥；实测界面不能直接调用 Node、shell 或任意文件接口，越会话请求被拒。原生进程启停、异常退出可管理，不将它无法访问包外文件作为验收条件 |
| 保存恢复 | 退出应用后恢复到已确认状态，公共/私有/剧情相符；未保存变化不冒充已保存 |
| 公共结算 | 一场真实战斗更新原玩法应有的奖励/成长/物品/状态；重复确认不重复发放 |
| 保存故障 | 提交前后各一次真实进程中断，重启得到完整旧状态或完整新状态，不出现半次结算 |
| 剧情回档 | 回到战前节点，剧情、公共奖励和插件状态一起恢复；旧实例回包被拒绝，再次游玩正常结算 |
| 管理卸载 | 活跃实例阻止管理；退出后列出依赖会话，删除成功再卸载；重启不偷偷重装 |
| 空插件环境 | 全部玩法包卸载后，基本聊天、世界书与会话管理仍可用 |

浏览器与 Electron 分开记录，构建不能替代原生运行。PC 视觉/窗口验收沿用项目既定五尺寸、相关主题和窗口模式，不增加移动端或云端部署矩阵。优先针对实际改动测试，最终再跑项目要求的全量入口。

## 8. 本轮交付边界

对外开发验收以独立小游戏示例为准：作者仅依赖公开模板/SDK，在桌面内完成玩法、保存/恢复、公共结算和回档。大型引擎集成不作为验收要求；核心供外部项目调用仍保留接口边界，不先建设另一套 SDK 平台。

2026-10-08 的方案交付仅更新设计、任务队列与历史记录，未实施新存储、删除旧实现、修改真实存档、重启服务或停止其他聊天。此后独立 S1 实施不改写那次交付的边界；本次文档整理也不执行这些操作。
