## 页面结构

左侧为封面与标题组成的书列表，保留新建、导入及用途筛选。没有封面的书显示统一的书籍占位图；长标题不得撑破布局。新建使用应用内表单，不依赖桌面端不支持的原生 prompt。

右侧顶部为世界书介绍栏：封面、名称、简介、整书 Token 估算、导出。名称、简介和封面可编辑并自动保存。移除手填预算、复制、会话绑定、全局默认和整书保存按钮，隐藏来源说明。

条目列表以阅读为默认状态：启用勾选、拖动手柄、标题、简短属性及折叠按钮。停用条目置灰但仍可阅读与重新启用。展开显示完整 Markdown，在展开区域切换编辑；保留名称、正文、触发词、分组、分类和常驻设置。隐藏字段不重置、不删除。

依赖作为条目的缩进子级逐层展开，移除每行关系下拉和添加依赖菜单。重复引用、环与缺失目标须能终止并说明，不得无限递归或一次渲染全书正文。

## 数据与交互

- Token 为固定算法的内容规模估算，使用现有后端中文字符与其他字符的估算口径；不调用 LLM，不把估算值写成实际截断上限。
- 自动保存合并连续输入并串行提交；响应不可覆盖更新的草稿。保存中、成功和失败可辨认，失败保留输入并可重试，切书不串写。
- 拖动提交整书顺序，必须原子持久化。旧书未显式排序时保留旧排序兼容；显式排序后，条目列表、节点视图及实际匹配顺序一致。
- 稳定层与动态层仍按现有注入纪律分开，拖动不能把触发条目塞入稳定前缀；各层内遵守条目顺序。
- 封面、简介和顺序需要最小后端支持，刷新、重新加载和项目格式导出回读后仍保留。
- “分类与载入”入口隐藏；旧入口归一到条目页，不产生空白页。节点页原有配置修改仍须具备可用的保存路径。

## 自动保存与导出的审核约定

以下约定补充前节的连续输入、版本确认与草稿生命周期，维护保存协调器时必须一并检查：

- 新条目使用稳定 UID，慢请求中继续输入不重复创建；创建途中删除后，后续排队保存不能使条目重新出现。
- 成功响应只能确认对应版本的任务；离开页面再回来后，旧请求不能删除新实例的待保存草稿。
- 尚未填写正文的新条目切书后仍可找回并继续编辑或删除，不能留下不可见却阻止导出的任务。
- 编辑正文不得重新拆分隐藏的辅助触发词，也不得重置其他隐藏设置。
- 导出先等待当前书的待保存内容，失败时保留草稿并明确提示。
- 节点页依赖编辑保留局部配置保存入口；分类与载入的旧跳转收敛到条目页。

这些条目记录审核范围，不代表自动宣布通过；最终需要代码复核与行为验证。

## 交付与验收

当时分工为 GPT Sol 实现、主代理审核、独立验收代理检查后端与回归。开发采用隔离 worktree，验收采用临时数据和独立端口；这是该次交付条件，不是今后必须使用的模型配置。

验收场景：

1. 新建空书并进入详情；输入名称、简介、封面，刷新后仍存在。
2. 新增及编辑条目，Markdown 全文正常阅读；启用、常驻、触发词、分组和分类保存正确。
3. 快速连续输入、保存失败及切书期间不丢稿、不串写；隐藏旧字段仍保留。
4. 拖动重排，重新加载后顺序不变；实际匹配与 Prompt 预览遵守同一顺序。
5. 依赖缩进可逐层阅读，环和重复引用有限展开。
6. 界面没有被要求移除的控件；长标题、长正文和当时约定的窄窗口可用。当前仅面向 PC，验收按[前端设计规范](../design/frontend-design-guidelines.md)的五组内容区与窗口模式执行。
7. 世界书后端回归、前端契约脚本和生产构建通过。统一测试入口若存在基线失败，逐项区分，不将局部通过称为全量通过。
