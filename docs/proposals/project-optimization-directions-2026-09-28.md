# Ark Tavern 项目优化方向

本文保存 2026-09-28 的产品与工程建议，供选择具体优化任务时比较收益、成本与验收方式。原则是：**作者决定关键事实，AI 丰富过程，程序落实后果。**优先让已有能力组成可靠、易上手且可持续创作的完整体验。

> 建议日期：2026-09-28；优先级不代表已排期或已授权实施。
> 最近核对：2026-10-11（主线 `7344cea` 的相关源码与现有文档静态核对；未运行测试、构建、真实模型评测或试玩）。

[本地单机插件方案](local-plugin-minimal-plan.md)及其本地实施队列另有范围与状态。本文的全项目方向不替代该队列，也不把独立实施区的进展写成主线能力。

## 阅读与决策方式

建议按“可靠的完整冒险 → 外部用户独立开局 → 外部作者独立交付作品”推进。性能测量和关键回归贯穿各阶段，具体投入由真实数据决定。

| 方向 | 要解决的问题 | 放行依据 |
|---|---|---|
| 选择与后果 | 文本中的承诺能否落实到状态，恢复和回档是否一致 | 同一短篇不同路线的结局、资源、恢复与回档可重复验证 |
| 完整短篇 | 平台能力能否组成无需现场解释的体验 | 目标用户独立完成，卡点与解释次数有记录 |
| 创作工具 | 作者能否定位缺失内容、试跑并分享作品 | 外部作者无需改宿主源码即可交付可玩作品 |
| 首次使用 | 没有开发环境的用户能否安装并成功开局 | 干净机器上的安装、启动、模型检查与第一轮通过 |
| 每轮性能 | 等待发生在哪一步，优化是否改善体感 | 可比场景和模型配置下测量，并确认状态行为不退化 |
| 高风险工程链路 | 流式响应、重试、切会话和回档交错是否可靠 | 定向回归、构建与关键浏览器流程分别提供证据 |

## 分析依据与边界

原建议依据架构文档、项目问题记录，以及叙述与大纲、会话回档与快照、战斗结算、世界书工作台、Electron 打包配置的部分源码检查；不构成完整代码审计。此次整理核对相关入口和建议的适用范围，保留原讨论结论。

没有玩家留存、作者效率或成本基线数据，收益判断仍是待验证假设。历史问题应在实施前重新复现；文档或源码中的能力不能作为运行质量证明。项目已是通用世界书平台，不沿用旧的方舟专用定位、自动安装示例假设或已移除的 AI 依赖构建方案。

## 1. 选择与后果的可靠性

已有剧情分支、回档、战斗结算和状态快照，应围绕它们验证闭环。[剧情规则](../design/narrative/story-rules.md)已提供作者声明的条件与效果，但这不证明每部作品都正确配置了规则或完成了端到端验收。

原讨论引用的问题包括开场泄露后续章节、叙述未提交任务状态、最后节拍缺少终态，以及“灰灯渡口”战前绕行缺结构化结算、结局事实仍受模型一致性限制。这些是历史信号；当前未解决范围与历史证据分别查看[工程笔记](../notes.md)，不能将原缺口清单全部照搬为当前故障。

建议逐项检查：

- 任务完成、关键人物生死、物品获取和路线选择是否由结构化状态确认，而非只存在于叙述中。
- 战斗、谈判、绕行是否都能形成正式后果，避免只有战斗胜利才算推进。
- 回档是否一起恢复任务、角色数值、分支和知识范围。
- 剧情是否具有明确结束状态，并在结束后阻止误推进。
- 世界事实与角色知识是否区分，避免后续剧情和秘密提前泄露。
- 重试、刷新与重复请求是否保持幂等，避免重复奖励或推进。

**验收方式：**同一短篇走不同路线，执行刷新、重载、回档及失败重试，核对关键事实、资源与结局；只将已复现的问题转成回归用例。程序状态与模型设定一致性分别验证。

## 2. 用一个完整短篇牵引优化

原建议选一个 30–60 分钟的示范冒险，检验无需开发者现场解释也能完成的体验。此时长是内容目标，尚无实际试玩数据证明。

最小作品应包含一次有明显后果的选择、一条非战斗路线、一场有叙事意义的战斗、至少两个真正不同的结局，以及中途退出、恢复和回档。背景、角色、音乐与结局反馈也要进入完整流程。示例仍由用户显式安装，不恢复自动安装内容。

**验收方式：**邀请少量目标用户独立试玩，记录卡点、人工解释次数、完成情况、等待感受和选择后果是否清晰。先形成基线，再设改善目标；资源数量不替代可玩质量。

## 3. 创作工具围绕完整作品

世界书、角色、节点图和演出资源已有基础。作者需要知道作品还缺什么、设定为何未出现、修改会影响哪里，以及如何隔离试跑和分享。

| 作者任务 | 建议能力 | 验收条件 |
|---|---|---|
| 准备发布 | 检查入口、角色、资源、分支落点和结局完整性 | 错误定位到具体内容，并提供修复入口 |
| 排查注入 | 解释条目未加载或未触发的原因 | 解释对应真实注入链路与请求上下文 |
| 修改大纲 | 预览失效引用、演出绑定及旧会话影响 | 更新前看见影响，不静默破坏引用 |
| 单幕试跑 | 从指定节拍建立隔离测试会话 | 前置状态明确，不污染正式存档 |
| 分享作品 | 在干净环境检查整书资源与依赖 | 无作者本机隐藏资源也能打开和游玩 |

当前 Prompt 预览面向整本启用书，并不代表实际下一轮请求；因此“解释真实未注入原因”仍需要补足上下文与诊断能力，不能只换预览文案。全局依赖配置的 `LoadTab` 尚未挂载，配置草稿保存条不可达，会话依赖微调仍可用；入口与已知边界见[世界书工作台方案](worldbook-workbench-redesign.md)及[工程笔记](../notes.md)。

实施前应决定哪些配置需要简单入口、哪些属于高级能力。优先可解释的检查和可控辅助操作，不直接恢复已移除的 AI 自动猜依赖功能。

## 4. 降低首次使用门槛

当前 README 仍说明从源码运行；`frontend/package.json` 的打包文件范围只有前端与 Electron 产物。存在打包目标，不证明安装包已经自包含后端或在干净机器可用。

原建议先专注 Windows：提供自包含运行包或经过干净机器验证的安装流程；首次启动检查后端、模型连接与可写目录。模型检查除连通性外，还应验证所需结构化输出能力。

玩家入口突出故事与行动，作者入口按需展开配置；使用作品声明的合理默认值，减少从选择作品到第一轮的配置负担。此目标不要求立即整体重做视觉。

**验收方式：**在无开发环境的机器验证安装与开局，记录首次成功开局耗时、成功率和人工解释次数。现在的最短操作路径见[入门教程](../tutorial.md)，它不等于上述分发验收完成。

## 5. 按每轮链路测量性能

当前叙述包含文本生成、结构化提取，以及按条件发生的偏离评估。独立回忆摘要链已退休，但不能由此推断每轮只会发生固定次数的模型调用；具体链路见[两阶段叙述](../design/narrative/two-phase-narration.md)。

先测点击发送到首字出现、叙述结束到选项可操作的时间；同时记录每轮调用次数、输入/输出 token、重试与降级比例，以及完整冒险耗时和费用。用户等待感受可能来自模型、提取或其他步骤，需测量后定位。

再依据数据调整偏离评估条件、上下文预算、缓存复用和可安全并行的步骤。保留常驻稳定层与触发动态层的注入纪律；界面区分“故事正在生成”和“结果正在确认”，不提前提交未经校验的状态。

**验收方式：**固定场景与可比模型配置，对比前后数据并核对分支、状态及错误处理。[历史性能记录](../perf/perf-round-latency.md)可作为测量方法参考，其中旧链路数字不直接作为当前性能基线。

## 6. 工程优化围绕高风险链路

每次功能修改处理相应耦合点，优先维护可重复的状态验证和模型评测：

- 建立固定剧情状态用例，以及真实模型遵守设定、保留玩家选择的评测。
- 对当前仍有效的预期失败先复现再修复；历史严格 `xfail` 数量不能直接当作当前缺口或通过数。
- 建立测试、构建和关键浏览器流程的门禁。
- 验证流式响应、切会话、失败重试与回档交错时的状态一致性。
- 随功能拆分高耦合模块，以职责和可验证边界为依据，不以文件长度为主要目标。
- 对内容更新、资源缺失和受支持存档结构提供检查与恢复路径；不因此扩大为项目旧内部格式的通用迁移支持。

程序测试回答“状态是否正确”；真实模型评测回答“是否遵守设定、保留玩家选择”。两者不能互相代替，构建也不能代替浏览器或 Electron 验收。

## 建议阶段与投入取舍

| 阶段 | 交付 | 放行依据 |
|---|---|---|
| 可靠的完整冒险 | 一个精品短篇及已复现状态缺口的修复 | 不同路线、终局、恢复与回档可重复验收 |
| 独立开局 | Windows 分发与首次使用流程 | 外部用户无需开发者协助完成安装及开局 |
| 独立创作 | 发布检查、局部试跑、完整分享与更新检查 | 外部作者无需修改宿主源码即可交付可玩作品 |

性能测量与关键回归贯穿各阶段。若按本方向单独选一个主题，原建议是以精品短篇为载体，验证选择、结算、终局与回档的可靠性；不据此更改已经确认的插件实施顺序。

暂缓新增战斗体系、大规模视觉翻新、社区市场与全面架构重写，除非具体证据表明它们能解决本轮确定的体验问题。
